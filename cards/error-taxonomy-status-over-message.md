# Error taxonomy: status fields over message regex

## The failure mode

LongHorizon-Harness's `CommandAgentAdapter` correctly returned `EpisodeResult(status="timeout")` after the role budget elapsed, but the generic provider-error classifier matched the adapter's **own synthesized** `Episode timed out after ...` text against its network-timeout regex. Result: a recoverable local timeout was reclassified as a provider network failure → Manager terminated the whole run destructively.

## The rule

**Classification must key on structured status fields, never on matching message text against error-pattern regexes.** A synthetic message (generated by the same codebase doing the classification) can trivially collide with a provider-error pattern, turning a recoverable event into a fatal one.

Corollary: local budget exhaustion (timeout, token cap) ≠ provider failure (auth, quota, network). The former is recoverable with partial output preserved; the latter is often terminal. Mixing them destroys state that a recovery loop could have used.

## Transferable to our stack

- Subagent timeout handling: Copilot API ~60s streaming idle timeout is a *local budget* event — partial output should be preserved as first-class state and the main agent takes over, not discarded as a failed episode.
- Anywhere we grep logs for error strings to decide severity: prefer explicit status/exit-code fields.
- Same taxonomy lesson as [[study-saturation]] signal taxonomy and FlowForge branch-selection: *what counts as a trigger matters more than the trigger mechanism* — and misclassification of the trigger is the silent killer.
