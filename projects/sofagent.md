## What It Is

A **soft constraint layer** for AI agents — Markdown rulebooks + bash scripts. Not a framework, not a skills marketplace. Pure governance methodology: tell agents what to do, what not to do, when to stop.

**Core architecture**: 3-layer loading chain

| Layer | File | Nature |
|-------|------|--------|
| 1. Constitution | SKILL.md (inline) | Immutable. 4 hard rules + 10 principles |
| 2. Reflection | think.md | Auto-generated error log (mistakes from past tasks) |
| 3. User rules | rules.md | User-customizable, highest priority |

Loading order follows Lost in the Middle research — SKILL.md first (high attention), rules.md last (high attention). think.md in the middle (reference, not hard constraint).

**Orchestration engine**: Only fires for 🔴 complex tasks. Uses `ao compose` (agency-orchestrator npm package) for task decomposition + role matching. Falls back to manual decomposition without it.

## Key Design Decisions

### 500-char Rule
Each constraint file capped at ~500 chars. Based on usage observation + Lost in the Middle (Liu et al., 2023). Beyond 500, agent compliance drops — rules get buried in long text.

### Compensatory vs Systematic Engineering
Explicit distinction: "compensatory" = patches for current model limitations (expire with upgrades); "systematic" = permanent challenges (context overflow, control flow drift, error propagation, feedback absence). sofagent targets systematic only.

### Progressive Thinning (4-Level Orchestration Depth)
Repeated successful tasks get lighter orchestration. Success → trust builds → overhead reduces. Failure → roll back to full orchestration. Sliding window (last 5 runs) for rollback decisions.

### Circuit Breaker for Sub-Agents
Per-agent state machine: CLOSED → (3 consecutive failures) → OPEN (30s cooldown) → HALF_OPEN (probe 1 attempt) → success → CLOSED / failure → OPEN. Prevents sub-agent cascading failures.

### Memory Write Threshold
Only write to think.md when: (1) same error repeated ≥2× in session, (2) verifiable destructive consequence (exit code ≠0, file deletion, API 4xx), or (3) user explicitly says "remember this." Prevents noise accumulation.

### Memory Decay
30-day-old entries: weight ×0.3. 60-day-old: archived to think.archive.md, removed from loading chain. Compression triggered every 7 days or when think.md >5K tokens.

### Separated Review (OpenClaw Only)
On OpenClaw: `session.spawn` creates independent reviewer sub-agent (flash model) — only sees task/logs, not execution context. Engineering isolation.
Non-OpenClaw: same agent re-reads task/logs as "primary evidence" — prompt-level constraint, no mechanism guarantee. Tested: loading chain hit rate 0/3 to 1/3 on WorkBuddy.

1. **Memory write threshold** — explicit bar before writing lessons. Our beliefs-candidates has Triple Verification but less explicit on "don't write noise"
2. **Progressive thinning** — reduce orchestration overhead for proven-successful task patterns. We don't have this; every FlowForge run pays full overhead
3. **Circuit breaker for sub-agents** — named pattern for cascading failure prevention. We handle this ad-hoc
4. **500-char rule for constraint files** — based on attention research. Our DNA files are significantly longer (AGENTS.md is 300+ lines)

## Applied (2026-06-23)

**Pattern adopted: Circuit breaker for workflow/subagent failures**

Created `tools/circuit-breaker.sh` — state machine (CLOSED→OPEN→HALF_OPEN) that tracks consecutive failures per workflow key. Integrated into:
- `tools/study-saturation-gate.sh` (Layer 0, before mode availability checks)
- `tools/workflow-guard.sh` (general guard for all FlowForge workflows)

Design aligned with sofagent's per-agent circuit breaker:
- Threshold: 3 consecutive failures → OPEN (blocks further attempts)
- Cooldown: 30 min → HALF_OPEN (allows 1 probe attempt)
- Success always resets to CLOSED
- Per-key isolation (each workflow/subagent tracked independently)

Key difference from sofagent: ours is a standalone bash tool (no framework dependency) integrated at pre-check gates rather than inside the agent spawn path. Same state machine semantics.

**Behavioral change**: Previously, if workloop cron fired every 30 min and kept failing (e.g., 6 consecutive errors on 06-22), nothing prevented continued token waste. Now, after 3 consecutive failures the circuit opens and blocks further attempts until cooldown. Saves tokens, reduces noise, makes failure visible.

## Applied (2026-06-24)

**Progressive thinning pattern applied to dna-preflight.sh**

Implemented the core progressive thinning insight: reduce orchestration overhead for proven-ineffective behavioral reminders. When a pattern has been surfaced by dna-preflight on 3+ unique days without resolution, it's demoted from the top-3 display (score penalty -5) and shown only as a compact summary count.

**Measured behavioral change:**
- Before: top-3 slots consistently occupied by 6 chronic recidivists (3-5 days each). No behavioral improvement from repeated exposure.
- After: fresh violations surface (study-no-gradient-justified, quality-proof-for-optimizations) — patterns where a reminder can still drive change.
- Chronic patterns noted in one-line summary, not lost, but attention redirected.

**Design choices:**
- Penalty-based (-5) rather than hard filter — if a chronic pattern gets fresh reinforcement (new violation today), it can still overcome the penalty
- Detection uses `.preflight-log` unique-day counting (already existed), so zero new tracking infrastructure needed
- Combined with [[tokdiet]] per-strategy backoff: instead of shutting down the whole preflight (blanket), only the degraded strategy (chronic patterns) gets demoted

**Difference from SofAgent's full design:**
- SofAgent's thinning is about entire governance layers (skip loading the 3-layer chain for familiar tasks)
- Our application is narrower: thin the output of a specific tool, not skip the tool entirely
- Structural fixes (recommended by the recidivism alert) remain the full resolution; thinning is the interim noise reduction
